> 在服务化渲染随着团结引擎普及之前，使用Run As Library的方式，是 3D 应用模块嵌入安卓应用的主流方式。在这种方式下，默认是以 SurfaceView 来承载渲染的。通过之前我分享的文章可以了解到，SurfaceView 是独立于安卓的 View 树，以一种挖洞的形式渲染的。

会不会有什么情况下还有一个SurfaceView要叠加在 3D 应用之上？在古法编程时代，确实遇到过这样一个特殊场景。

# 技术约束

## **需求描述**

- 画面 A（Unity3D 画面）是渲染在 SurfaceView 上的。
- 画面 B（视频流）也是渲染在 SurfaceView 上的。
- 视觉上，画面 B 要以圆角矩形区域覆盖画面 A。本质上也可以认为这两个画面只是要同时显示，只不过画面 A 是全屏的，画面 B 是一块圆角矩形小窗。

## 难点描述

- 画面 A 必须使用 SurfaceView，要改也来不及。
- 画面 B 必须使用 SurfaceView，也许是因为渲染效率高，也许是开发方不愿意改，反正不能用 TextureView。
- 受制于 SurfaceView 的独立渲染的机制，Android 当前版本没有好办法去稳定高效地叠加两张 SurfaceView。

> 于是就产生了这么一个别扭的方案：
>
> **在 3D 的画面上再挖一个圆角矩形，叫挖洞也好、叫透出也行，就是要空出这么一个圆角矩形区域，去露出安卓那边维护的另一个 SurfaceView。**

# 挖洞实现

通过后处理系统，在最终渲染阶段对画面进行遮罩处理。

> **部署方式：**对于Unity来说，就是：URP Renderer Data（URP渲染器数据）→ Add Renderer Feature。然后创建一份shader文件，用这个shader创建一个材质，把材质赋给刚刚那个Render Feature。事件选择 AfterRenderingTransparents。

## 示例代码

```hlsl
// 1. 支持遮罩变体（可通过shader变体控制是否启用）
#pragma multi_compile _ _VIEWPORT_MASK

// 2. 全局遮罩参数（从Unity端通过Shader.SetGlobal传递）
float4 _ViewportRect;        // 遮罩区域：左边缘距离，下边缘距离，宽，高
float _ViewportRadius;         // 圆角半径
float _ViewportAlpha;          // 遮罩透明度

// 3. 圆角矩形距离场函数（SDF算法核心）
float roundedBox(float2 uv, float2 size, float radius)
{
    float2 q = abs(uv) - size + radius;
    return length(max(q, 0.0)) + min(max(q.x, q.y), 0.0) - radius;
}

// 4. 片元着色器：逐像素计算遮罩
half4 FragmentShader(Varyings input) : SV_Target
{
    half3 finalColor = SampleSceneColor(input.uv);
    half alpha = 1.0f;
    
    // 5. 遮罩计算（如果启用_VIEWPORT_MASK变体）
    #if _VIEWPORT_MASK
    {
        // 5.1 计算当前像素到遮罩区域的距离
        float2 screenSize = float2(2560, 1600);  // 屏幕分辨率
        float2 center = _ViewportRect.xy + _ViewportRect.zw * 0.5;
        float distance = roundedBox(input.uv * screenSize - center, 
                              _ViewportRect.zw * 0.5, 
                              _ViewportRadius);
        
        // 5.2 距离场转透明度：区域内alpha=1，区域外alpha=0
        // step函数在GPU上执行平滑插值，自然抗锯齿
        alpha = saturate(step(0, distance) + _ViewportAlpha);
    }
    #endif
    
    // 6. 输出最终颜色：原色乘以遮罩透明度
    return half4(finalColor * alpha, alpha);
}
```

## 关键方法

### 1. 圆角矩形函数

计算点到圆角矩形边界的距离，内部点距离为负，外部点距离为正。

```hlsl
float roundedBox(float2 uv, float2 size, float radius)
{
    float2 q = abs(uv) - size + radius;
    return length(max(q, 0.0)) + min(max(q.x, q.y), 0.0) - radius;
}
```

### 2. 距离场转透明度

将上面的距离场值转换为二值化的透明度（0或1）。

```hlsl
alpha = saturate(step(0, distance) + _ViewportAlpha);
```

> **抗锯齿效果：** GPU的离散采样特性会在遮罩边缘自然产生像素级的过渡效果，无需额外的抗锯齿算法。但这种效果依赖于屏幕分辨率是够大的。

# 其他

使用这个技术方案，还需要：

1. 调用 setZOrderOnTop(true) 或 setZOrderMediaOverlay(true) 置顶画面A
2. SurfaceView 需要设置 setFormat(PixelFormat.TRANSLUCENT)
3. 同时还会需要信号接收，事件处理，在事件中设置Shader参数等等。这里就不赘述这个业务逻辑上的常见过程。

但是会需要额外提一点的是，上述这种挖洞的画面融合做法，最容易出现的问题就是：画面 A 的遮罩（挖的洞）与画面 B 的显示隐藏存在时序问题。需要考虑在通信上做双向确认或收到变化信号之后等帧。

## 结语

在Render As Service + Android App View的推动下，我想以后使用 TextureView 或直接嵌入安卓视图的情况会越来越多，那么就可能不会存在无法排列这两个画面的层级的问题。如果哪天再遇到了两个 SurfaceView 嵌套的场景，这篇文章可以做个参考。
