> Before service-based rendering became widespread with the Tuanjie Engine, Run As Library was the mainstream way to embed a 3D application module into an Android app. In that mode, rendering is carried by a SurfaceView by default. As you can learn from my previously shared articles, a SurfaceView sits outside Android's View tree and renders in the form of a punched hole.

Could there ever be a case where yet another SurfaceView needs to be stacked on top of the 3D application? Back in the old-school programming days, I did run into such a special scenario.

# Technical Constraints

## **Requirements**

- View A (the Unity3D view) renders on a SurfaceView.
- View B (a video stream) also renders on a SurfaceView.
- Visually, view B should cover view A within a rounded-rectangle region. Essentially, you can also think of the two views as simply needing to display at the same time — except view A is fullscreen, and view B is a small rounded-rectangle window.

## The Difficulties

- View A must use a SurfaceView, and there's no time to change that.
- View B must also use a SurfaceView — maybe because of its rendering efficiency, maybe because the vendor won't change it — in any case, TextureView is not an option.
- Constrained by SurfaceView's independent rendering mechanism, the current version of Android has no good way to stack two SurfaceViews stably and efficiently.

> And so this awkward solution was born:
>
> **Punch another rounded rectangle into the 3D view — call it a hole or a see-through cutout — the point is to leave that rounded-rectangle region empty, so the other SurfaceView maintained on the Android side can show through.**

# Implementing the Hole

Through the post-processing system, mask the frame during the final rendering stage.

> **Deployment:** For Unity, that means: URP Renderer Data → Add Renderer Feature. Then create a shader file, create a material from that shader, and assign the material to the Render Feature you just added. Choose AfterRenderingTransparents as the event.

## Example Code

```hlsl
// 1. Support the mask variant (can be toggled via a shader variant)
#pragma multi_compile _ _VIEWPORT_MASK

// 2. Global mask parameters (passed from the Unity side via Shader.SetGlobal)
float4 _ViewportRect;        // Mask region: distance to the left edge, distance to the bottom edge, width, height
float _ViewportRadius;         // Corner radius
float _ViewportAlpha;          // Mask opacity

// 3. Rounded-rectangle distance field function (the core of the SDF algorithm)
float roundedBox(float2 uv, float2 size, float radius)
{
    float2 q = abs(uv) - size + radius;
    return length(max(q, 0.0)) + min(max(q.x, q.y), 0.0) - radius;
}

// 4. Fragment shader: compute the mask per pixel
half4 FragmentShader(Varyings input) : SV_Target
{
    half3 finalColor = SampleSceneColor(input.uv);
    half alpha = 1.0f;
    
    // 5. Mask computation (if the _VIEWPORT_MASK variant is enabled)
    #if _VIEWPORT_MASK
    {
        // 5.1 Compute the distance from the current pixel to the mask region
        float2 screenSize = float2(2560, 1600);  // Screen resolution
        float2 center = _ViewportRect.xy + _ViewportRect.zw * 0.5;
        float distance = roundedBox(input.uv * screenSize - center, 
                              _ViewportRect.zw * 0.5, 
                              _ViewportRadius);
        
        // 5.2 Distance field to alpha: alpha=1 inside the region, alpha=0 outside
        // The step function yields smooth interpolation on the GPU, giving natural anti-aliasing
        alpha = saturate(step(0, distance) + _ViewportAlpha);
    }
    #endif
    
    // 6. Output the final color: the original color multiplied by the mask alpha
    return half4(finalColor * alpha, alpha);
}
```

## Key Methods

### 1. The Rounded-Rectangle Function

Computes the distance from a point to the rounded-rectangle boundary: negative for interior points, positive for exterior points.

```hlsl
float roundedBox(float2 uv, float2 size, float radius)
{
    float2 q = abs(uv) - size + radius;
    return length(max(q, 0.0)) + min(max(q.x, q.y), 0.0) - radius;
}
```

### 2. Distance Field to Alpha

Converts the distance field value above into a binarized alpha (0 or 1).

```hlsl
alpha = saturate(step(0, distance) + _ViewportAlpha);
```

> **Anti-aliasing effect:** the GPU's discrete sampling naturally produces pixel-level transitions at the mask edges, with no extra anti-aliasing algorithm needed. But this effect depends on the screen resolution being large enough.

# Miscellaneous

Using this technical approach also requires:

1. Call setZOrderOnTop(true) or setZOrderMediaOverlay(true) to bring view A to the top
2. The SurfaceView needs setFormat(PixelFormat.TRANSLUCENT)
3. You'll also need signal reception, event handling, setting shader parameters inside events, and so on. I won't go over that common business-logic plumbing here.

One extra point worth raising: with this hole-punching approach to frame compositing, the most common problem is a timing issue between view A's mask (the punched hole) and view B's show/hide. Consider a two-way confirmation over the communication channel, or waiting a few frames after receiving a change signal.

## Closing

Driven by Render As Service + Android App Views, I expect the use of TextureView or directly embedded Android views to become more and more common, in which case the problem of being unable to order these two views' layers may simply disappear. If you ever run into a nested-two-SurfaceViews scenario again, I hope this article serves as a reference.
