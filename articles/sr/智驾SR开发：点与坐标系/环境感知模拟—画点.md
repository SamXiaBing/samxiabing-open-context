# 智驾SR开发：点与坐标系

> 做3D HMI开发这些年，一直想把这块的知识点慢慢整理出来。这一系列内容我会从应用层开发的实际经验出发，更多是个人的沉淀和复盘——毕竟环境感知模拟（SR - Surrounding Reality）开发的资料相对小众，要是我的整理能帮到正在做这块的你，那就再好不过了。

对任何3D引擎来说，**点**都是构建虚拟世界最基础的单元，比如一个三维模型文件，它的大部分信息其实是在描述点（点的空间坐标、法线方向、顶点颜色等）。 而做智驾SR开发，我们最关注的是 **点的空间坐标 + 所属坐标系**。

无论是自车位置点、车道线顶点，还是占用网格点，位置都靠X/Y/Z三个值描述。但可能也会遇到不同厂商的接口单位不统一，有的用毫米（mm）有的用米（m）。

---

# 坐标系

为什么开篇要聊"点和坐标系"？我们常说"画点"，这个"画"其实很有意思：点的数据拿到手，不是直接就能用，得先搞懂它在哪个坐标系里，才能把它放到3D世界正确的位置上——同一个点，换个坐标系，位置就完全不一样了，这个转换的过程，就是我们SR开发绕不开的基础。

## 经纬度（LLH）

LLH就是经度、纬度、高程这三个数。每个位置点，都有唯一的经纬度。全球通用，缺点也一样明显：**精度不够**，尤其GPS信号差的时候。所以这些场景会用到它：  
（1）在室外，定位自车目前的位置，以这个位置去匹配需要加载的内容，比如地图瓦片信息。  
（2）作为一个参考点，当做转换成其他坐标系的原点。  
（3）某些建图功能用它来定位绝对地理坐标，下次走到了这里，要触发相关记忆功能。

> LLH的高程是 **WGS84** 椭球高，不是日常说的海拔高度（正高）。直接使用可能有偏差，项目中通常需要做转换。**WGS84** 是一个为了数学计算方便而定义的、光滑的、规则的地球数学模型，它近似于地球的形状，但并非真实地表。

总的来说，LLH更适合用来表达宏观的绝对地理位置。

## 东北天坐标系（ENU）

ENU 指的是East（东）、North（北）、Up（天）三个方向的值。在SR开发过程中，地图数据这块最常见的就是它。

ENU 是局部坐标系，它得有一个原点当**参考点**，围绕这个点展开计算。地图数据里有一个关键字段，叫**参考点（ReferencePoint）**。它是当初建图时选定的一个LLH坐标。地图上所有点的ENU坐标，都是相对于这个点展开的。

在使用3D引擎进行开发时，对应关系是：

```
(E,U,N) → (X,Y,Z)
```

需要注意的是，这个对应关系不是行业强制标准，不同地图供应商可能会有不同的符号约定，对接供应商时，必须以接口文档的定义为准，不能沿用之前项目的经验直接转换。

## 自车坐标系（FLU）

自车坐标系的表达可能不唯一，比如我接触过的是FLU，即Forward（前）、Left（左）、Up（上）。自车坐标系是SR应用中关于自车**周边感知物，行车规划轨迹**最常用的坐标系，屏幕上出现的感知物，都是依靠这类坐标绘制的具体方位。

这套坐标系的设计逻辑，本质是"以车为中心的动态本地坐标系"——坐标系永远跟着自车走，感知结果不需要反复做全局坐标转换，非常适合实时更新的周边障碍物、车位信息，能大幅简化SR的实时绘制计算。需要注意：FLU的原点定义因智驾方案而不同，可能是车身后轴中心、也可能是整体中心位置，需要提前确认补偿偏移。

在开发中，对应关系是：

```
X = - L; Y = U; Z = F;
```

## Boot坐标系

还有一类几乎很少见到的点，它们属于Boot坐标系，也叫**开机坐标系**，是车身电脑开机时刻的位置原点。

为什么有这个？因为当GPS信号完全丢失的时候，LLH和ENU都没法用了——定位挂了。这时只能靠IMU推算自己的位置。推算的结果就在Boot坐标系里。

靠IMU推算的坐标精度会随着漂移越来越差，但GPS没信号的时候，这就是我们最后的"保底方案"。

## 坐标系对比总结


| 坐标系        | 全称   | 用途        | 精度  | 备注       |
| ---------- | ---- | --------- | --- | -------- |
| LLH        | 经纬高  | GPS原始定位   | 低   | 会漂移      |
| ENU        | 东北天  | 地图/定位     | 高   | 依赖参考点    |
| Boot       | 开机坐标 | IMU推算     | 低→中 | 保底使用     |
| 自车坐标系（FLU） | 前左上  | 感知输出和规划轨迹 | 高   | 以车辆中心为原点 |

# 实际场景

> 以下说明的数据过程，来自于工作中的实际数据

- 当车机启动之后，你将收到**自车坐标**，由于是刚开机，所以此时是 **Boot坐标系**。
- 当你驾驶一会儿之后，定位已经准备就绪，自车坐标的坐标系就变成了 **ENU坐标系**。
- 开在小区的道路上，车感知到的车位、车辆等，都是以 **自车坐标系（FLU）**给到坐标点/角点。
- 完成一次泊车路线的记忆之后，建图数据的点，会以 **LLH坐标系** 传输到应用层。

---

看起来只是三个简单的坐标值，但从LLH全局锚定，到ENU局部高精度映射，再到FLU动态跟随，最后加上Boot离线保底——整套坐标系体系其实是一套兼顾精度、实时性和可靠性的分层设计，这套分层设计就是我们搭建智驾3D世界最扎实的骨架。
