> SR 尤其是行驻泊一体化桌面，因为行驻泊的需求较为复杂，常因此会带来较多的机位状态需要实现。在业务一步步开发的过程中，也总是会遭遇各种各样的机位视角的 Bug。所以我想梳理 SR 相关的机位，本文局限于我接触过的业务需求范围，希望能在后续重新处理这块需求时，在技术落地上能看得更全一点。

## 一、SR 机位

SR 机位按业务分为四组：**行车环视**、**开门预警（DOW）**、**APA 自动泊车**、**HPA 记忆泊车**。部分机位在不同功能间复用（如 “三分之一屏视角” 同时服务行车与 APA）。

### 1.1 行车环视


| 机位       | 业务场景                          | 画面特征               |
| -------- | ----------------------------- | ------------------ |
| **低速环视** | 城市跟车、常规低速行驶（车速低于约 60 km/h）    | 近场透视，前后约 15 m 可见   |
| **高速环视** | 高速/快速路（车速达到约 60 km/h 及以上）     | 远距俯视，前后视野拉远，透视变形更小 |
| **顶视图**  | P 档驻车、环视雷达展示、用户主动切换俯视         | 垂直或近垂直俯视，360° 环视   |
| **三分屏**  | AVM画面弹出时使用，有时占左侧三分之一画幅，有时三分之二 | 画面中心向左平移           |

### 1.2 开门预警（DOW）

任一车门开启且存在来车风险时，**瞬切**到对应预警机位；关门后**恢复到进入 DOW 前的机位**。


| 机位       | 触发     |
| -------- | ------ |
| **左前预警** | 左前门开启  |
| **右前预警** | 右前门开启  |
| **左后预警** | 左后门开启  |
| **右后预警** | 右后门开启  |
| **左侧预警** | 左侧多门组合 |
| **右侧预警** | 右侧多门组合 |
| **双侧预警** | 左右同时开门 |


DOW 优先级最高，可打断行车、APA、HPA 任意当前机位。

### 1.3 APA 自动泊车


| 机位         | 业务场景         | 画面特征              |
| ---------- | ------------ | ----------------- |
| **泊车搜索**   | APA 激活后扫描车位  | 俯视/环视搜索，高亮可用车位    |
| **泊车执行**   | 选中车位后自动泊入/泊出 | 俯视泊入泊出过程          |
| **泊车+三分屏** | 泊车任意阶段，AVM弹出 | 搜索或泊入泊出过程 + 1/3 屏 |
| **泊车完成**   | 泊入结束确认       | 完成态俯视确认           |

### 1.4 HPA 记忆泊车

HPA 分两条线：**巡航**（沿记忆路线行驶）和**建图**（学习停车场）。机位与业务态信号相匹配。

**巡航（支持1/3 屏布局）**

与泊车搜索的视角很像，你也可以设计得有区别

![10](./10.png)

**建图**


| 机位            | 业务场景                 |
| ------------- | -------------------- |
| **建图待机**      | HPA 功能已开、车辆静止、等待开始建图 |
| **建图正常**      | 建图巡航采集               |
| **建图 2/3 正常** | 建图过程 2/3 屏布局         |
| **建图 2/3 顶视** | 建图过程顶视 2/3 屏         |
| **建图巡航 AVM**  | 环视视频与建图融合巡航          |
| **建图返回**      | 建图完成后沿记忆路线返回起点       |
| **建图结果**      | 建图完成，全览阅览地图          |
| **建图结果 AVM**  | 建图结果 + AVM 融合阅览      |


建图的视角没有固定的视角，所以这里不展示示意图。这里需要注意：

1. 有AVM和没有是不同的相机调整策略。
2. 巡航中看建图结果，和学习完成之后看建图结果也不同。

## 结语

相机的状态管理是3D HMI中一项很繁琐，很需要和多方打合的模块，尤其是如果还要做一镜到底时，相机模块将会是所有3D应用的公共模块。任何应用都需要向这个模块的开发者输入需求，做统一的开发落地。
