# 现象

**行驶中观察到感知车辆位置跳变，从道路线的动画来看，渲染本身不卡顿**。

从SR回放数据回放来看，收到的数据本身就存在跳变。可能是因为：**感知本身有噪声**：雷达或视觉检测到的物体位置的微小波动；也可能是**通讯链路有波动**：或是ADC的性能抖动，或是QNX收到之后的转发过程中丢了数据；也可能是**遮挡恢复之后的事实**：第二车道车辆遮挡第三车道上的一辆更高速行驶的车辆，第三车道车辆恢复显示的瞬间，有一些跳变。

总之，如果直接用原始数据显示，感知物在屏幕上就会抖动或瞬移，从体验角度来说，这是件有损用户信任的小事。

处理方式接触过两种（高斯卷积后面会讲到，但不是我之前用的）：

- **Lerp 插值**：每帧从当前位置向目标位置插值，一直在追赶。
- **卡尔曼滤波**：去预测一个值，获取一个最优的估计。

# 卡尔曼滤波

卡尔曼滤波的核心逻辑是：有一个测量值（智驾系统输出的方位数据），也有一个预测值（根据之前的运动趋势推测现在应该在哪儿），两个都不完全准，但可以加权融合。而更相信哪个值的这个系数K也是计算得到且变化的，越偏测量值，响应就会更明显更容易跳变，越偏预测值，就显得更平滑更滞后一些。

## 预设三个参数：

一个是 R 测量噪声：它代表传感器的测量精度，如果是毫米波雷达，假设测量精度 ±0.1m，那么就拿它的平方作为 R ，R = 0.01 m²，就是说 R 约等于精度方差。

![fig_kalman_params](./fig_kalman_params.png)

一个是 Q 过程噪声：它代表对变化趋势的判断和真实变化之间的误差，比较拍脑袋，靠一点点调。如果没有方向，可以先设成R的十分之一开始调，比如 0.001 m。

还有一个是 P 误差协方差：它的含义是表达对初始估计值的信任程度，相对于R来说，可以给一个10倍到100倍的值。它会随着计算迭代过程很快收敛，所以影响的是初期收敛过程，没太大所谓，所以下面预设 1.0 m²。

## 公式:

1. 当前估计值 = 上一次算的估计值（没有？那就拿第一帧测量值）
2. 误差协方差 P = 误差协方差 P  + 过程噪声 Q
3. 卡尔曼增益 K = 误差协方差 / (误差协方差 + 测量噪声 R)
4. 更新 新的估计值 = 当前估计值 + K × (本次测量值 - 当前估计值)
5. 更新 新的误差协方差 P = (1 - K) × 误差协方差 P

## 代码示意：

```csharp
public double Update(double measurement)
{
    kalmanGain = errorCovariance / (errorCovariance + measurementNoise); // 算增益
    estimatedValue += kalmanGain * (measurement - estimatedValue);       // 融合测量
    errorCovariance = (1 - kalmanGain) * errorCovariance;                // 更新协方差
    return estimatedValue;
}

```

## 数据举例

77GHz 前向毫米波雷达的典型精度指标 ：


| 测量维度 | 标称精度          | 对应 R 值（方差=精度²）         |
| ---- | ------------- | ---------------------- |
| 距离   | ±0.1 ~ 0.15 m | R_ρ = 0.01 ~ 0.0225 m² |
| 径向速度 | ±0.1 m/s      | R_v = 0.01 (m/s)²      |
| 方位角  | ±0.1° ~ 0.3°  | R_θ = 0.01° ~ 0.09°    |


以距离跟踪（20 Hz）为例：


| 参数            | 典型值      | 说明            |
| ------------- | -------- | ------------- |
| **R（测量噪声）**   | 0.01 m²  | 取测距精度 ±0.1 m 求平方 |
| **Q（过程噪声）**   | 0.001 m² | 取 R 的 1/10 量级 |
| **P₀（初始协方差）** | 1.0 m²   | 设大些，快速收敛      |


### **场景**

前方车辆在 50 米处匀速行驶，毫米波雷达每 50ms 输出一次距离测量值，带 ±0.1m 噪声。

### **初始状态（第 0 帧）**

- 估计值 x̂₀ = 50.0 m（第一帧测量值直接当初值）
- 误差协方差 P₀ = 1.0 m²
- Q = 0.001，R = 0.01

### **第 1 帧：收到测量值 z₁ = 50.08 m**


| 步骤       | 公式                                   | 计算                                | 结果           |
| -------- | ------------------------------------ | --------------------------------- | ------------ |
| 1. 预测估计值 | x̂_pred = x̂_prev                    | = 50.00                           | 50.00 m      |
| 2. 预测协方差 | P_pred = P_prev + Q                  | = 1.000 + 0.001                   | **1.001 m²** |
| 3. 卡尔曼增益 | K = P_pred / (P_pred + R)            | = 1.001 / (1.001 + 0.01)          | **0.990**    |
| 4. 更新估计值 | x̂_new = x̂_pred + K × (z - x̂_pred) | = 50.00 + 0.990 × (50.08 - 50.00) | **50.079 m** |
| 5. 更新协方差 | P_new = (1 - K) × P_pred             | = (1 - 0.990) × 1.001             | **0.010 m²** |


第一帧 K 高达 0.99，几乎完全相信测量值，因为初始 P 很大，滤波器对自己的预测没信心。但是新的P 从 1.0 暴跌到 0.01，只用一帧就接近了 R 的量级。

### **第 2 帧：收到测量值 z₂ = 49.93 m**


| 步骤       | 公式                                   | 计算                                  | 结果            |
| -------- | ------------------------------------ | ----------------------------------- | ------------- |
| 1. 预测估计值 | x̂_pred = x̂_prev                    | = 50.079                            | 50.079 m      |
| 2. 预测协方差 | P_pred = P_prev + Q                  | = 0.010 + 0.001                     | **0.011 m²**  |
| 3. 卡尔曼增益 | K = P_pred / (P_pred + R)            | = 0.011 / (0.011 + 0.01)            | **0.524**     |
| 4. 更新估计值 | x̂_new = x̂_pred + K × (z - x̂_pred) | = 50.079 + 0.524 × (49.93 - 50.079) | **50.001 m**  |
| 5. 更新协方差 | P_new = (1 - K) × P_pred             | = (1 - 0.524) × 0.011               | **0.0052 m²** |


第二帧 K 降到 0.52，测量和预测各信一半左右。测量值从 50.08 跳到 49.93，滤波输出只从 50.079 变到 50.001（变了 0.078m），**噪声被砍掉了将近一半**。

### **第 3 帧：收到测量值 z₃ = 50.02 m**


| 步骤       | 公式                                   | 计算                                  | 结果            |
| -------- | ------------------------------------ | ----------------------------------- | ------------- |
| 1. 预测估计值 | x̂_pred = x̂_prev                    | = 50.001                            | 50.001 m      |
| 2. 预测协方差 | P_pred = P_prev + Q                  | = 0.0052 + 0.001                    | **0.0062 m²** |
| 3. 卡尔曼增益 | K = P_pred / (P_pred + R)            | = 0.0062 / (0.0062 + 0.01)          | **0.382**     |
| 4. 更新估计值 | x̂_new = x̂_pred + K × (z - x̂_pred) | = 50.001 + 0.382 × (50.02 - 50.001) | **50.008 m**  |
| 5. 更新协方差 | P_new = (1 - K) × P_pred             | = (1 - 0.382) × 0.0062              | **0.0038 m²** |


第三帧 K 继续降到 0.38，滤波器越来越"自信"。测量值 50.02 只比预测值 50.001 偏了 0.019m，滤波输出微调了 0.007m，**平滑效果已逐渐明显了**。可以看到一个清晰的趋势：**K 逐帧下降，P 逐帧收敛，滤波器从不大自信变得心里有个数了**。

从第2和3步，可以看到，每一次Q拉高预期，R又降回来，到了稳态的时候，K其实是由Q和R决定的一个值。上述例子稳态时大约 27% 信测量、73% 信预测，这和 K ≈ √(Q/R) 的值近似，可以近似计算。

# 项目应用

## 数据缓存与滤波

每个感知物有一个`DataBuffer`对象，内部维护一个最多缓存5帧的队列，以及X和Y两个方向各一个卡尔曼滤波器：

```csharp
public class DataBuffer
{
    private Queue<PerceptionObject> _cache;      // 最多缓存5帧的队列
    private KalmanFilter _kalmanFilterX;          // X方向滤波器
    private KalmanFilter _kalmanFilterY;          // Y方向滤波器
    private PerceptionObject _filteredData;       // 滤波后的最优估计
    private PerceptionObject _displayData;        // 当前显示位置
}

```

## 数据输入

每帧新的感知数据到达时，调用`Add`方法，当感知物被遮挡后重新出现，位置可能差了几十米。如果直接用旧滤波器继续滤波，输出会从旧位置慢慢追到新位置，所以当距离超过阈值时，直接重置滤波器：

```csharp
public void Add(PerceptionObject data)
{
    if (_cache.Count == 0)
    {
        InitFilter(data.centerPositionX, data.centerPositionY); // 首帧初始化滤波器
        _filteredData.Clone(data);
    }
    else
    {
        // 计算新数据与上一次估计的距离，跳变太大说明被遮挡后重现，重置滤波器
        double dx = data.centerPositionX - _filteredData.centerPositionX;
        double dy = data.centerPositionY - _filteredData.centerPositionY;
        if (Math.Sqrt(dx * dx + dy * dy) > distanceFilter)
        {
            _cache.Clear();
            InitFilter(data.centerPositionX, data.centerPositionY);
        }
        _cache.Enqueue(data);
        if (_cache.Count > _maxCacheSize) _cache.Dequeue();  // 超出上限丢最旧
        PredictNextState();
    }
}

```

## 核心计算

对缓存中的多帧数据，逐帧执行卡尔曼滤波的Predict和Update：

```csharp
// 对缓存里的每一帧数据（X方向示意）逐个喂给滤波器
foreach (int x in positionX)
{
    _kalmanFilterX.Predict();          // 先预测
    _kalmanFilterX.Update(x);          // 再用测量值修正
}
_filteredData.centerPositionX = (int)_kalmanFilterX.GetValue(); // 取最优估计

```

卡尔曼滤波的收敛需要时间。对多帧数据逐帧迭代，滤波器能更好地收敛到稳定的估计值。缓存5帧是一个折中的经验值。

## 数据输出

卡尔曼滤波不是面向视觉的万能答案，在真正要指导渲染的时候，会再加一层Lerp平滑。

卡尔曼滤波和 Lerp 可以权当作是从两个层面出发去考虑的结果：前者要的是数据够干净，最优，去噪。而后者瞄准的渲染阶段的平顺动画。

这个可能和具体的智驾数据和系统情况有关，加不加根据实际表现可选：

```csharp
public PerceptionObject GetData()
{
    _timeElapsed += Time.deltaTime; // 收到新数据清零
    float t = _timeElapsed / duration;  // duration = 0.2s
    // 从当前显示位置向滤波后的位置插值
    _displayData.centerPositionX = (int)Mathf.Lerp(_displayData.centerPositionX, _filteredData.centerPositionX, t);
    return _displayData;
}

```

# 关于高斯卷积滤波

除了卡尔曼滤波，平滑感知物轨迹还有高斯卷积滤波。它经常被拿来和卡尔曼比较，通常它的定位是兜底方案。

高斯卷积滤波的本质是**窗口期内数据的加权平均**。假设一个3到5帧的数据窗口，把窗口里每一帧的位置按高斯分布的权重累加起来，两头权重小中间权重大，最后除以权重和得到平滑后的位置。

```csharp
// 3帧高斯卷积，权重按高斯分布 [0.1, 0.8, 0.1] 示意
float targetX = 0.1f * frameN2.x + 0.8f * frameN1.x + 0.1f * frameN.x;
float targetY = 0.1f * frameN2.y + 0.8f * frameN1.y + 0.1f * frameN.y;

```

高斯卷积滤波的本质，是对历史窗口内的数据做加权求和。窗口越大越平滑，但延迟也越大，通常会带来 3~5 帧甚至超过 100ms 的滞后。

它和卡尔曼滤波的根本差异在于：**高斯卷积是"平均"，卡尔曼是"估计"**。前者靠窗口把噪声中和掉，向历史妥协，遇到突变响应慢；后者能判断波动是真实运动还是噪声，既可以预估当前位置，又能在目标突变时通过重置滤波器立即响应，输出更贴近真实轨迹的最优估计。

然而，高斯卷积算法简单、性能好、几乎不消耗算力，在算力紧张的情况下，确实有它的价值。

选型的时候可以都写上去然后实际跑一跑试试，如果卡尔曼的CPU消耗有点高，也可以放到Compute Shader里面去试试。只要算力允许，就更值得考虑卡尔曼滤波。

# 结语

虽然讲了这么多，但是如果交付过程中真的遇到这种情况，座舱IVI这边大概率不会在问题之初就主动使用上述方法去做“优化”/"兜底"。从职能定位上来看，3D渲染做的是真实数据的表达，不应该丢弃数据的真实性去做视觉上的安慰，不应该以一个视觉交互塑造者的身份去自行理解并纠正行车感知安全数据。
